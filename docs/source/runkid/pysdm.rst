Running the 1-D KiD with PySDM
================================

The 1-D KiD can be run with PySDM, using PyMPDATA as the thermodynamic driver
from a backend within the PySDM repository.

Running PySDM
---------------

The script ``scripts/run_pysdm.py`` can be used to run the entire workflow
for an ensemble of runs of the PySDM 1-D KiD. For each member of the
ensemble, it consists of 4 stages:

1. :ref:`generating inputfiles<do_inputfiles_pysdm>`
2. :ref:`running, i.e. time-stepping, the PySDM 1-D KiD model<do_run_model_pysdm>`
3. :ref:`post-processing the PySDM 1-D KiD output<do_postprocess_pysdm>`
4. :ref:`plotting "quicklooks" of the post-processed results<do_plot_results_pysdm>`

Each stage can be turned on (the default is off) by calling ``run_pysdm.py``
with the associated flag for that stage, e.g. to run all the stages for
an ensemble called "your_ensemble" consisting of 3 runs you would do:

.. code-block:: console

  $ uv run python ./scripts/run_pysdm.py /path/to/your/build "your_ensemble" 3 \
      --do_inputfiles --do_run_model --do_postprocess --do_plot_results

To make things potentially easier, you can also choose to call this script through
the bash script ``run_sdm_1d_kid.sh``:

.. code-block:: console

  $ ./scripts/bash/run_sdm_1d_kid.sh [machine] [model] [run_flags] [path2sdm1dkid] [path2build] [python]


E.g. on Levante:

.. code-block:: console

  $ ./scripts/bash/run_sdm_1d_kid.sh levante pysdm \
       "--do_inputfiles --do_run_model --do_postprocess --do_plot_results" \
       ./ ./build $(uv run which python)

The following sections describe each stage in a bit more detail.


.. _do_inputfiles_pysdm:

Generating Inputfiles
~~~~~~~~~~~~~~~~~~~~~~~

For PySDM, the input file for each run in your ensemble is a configuration YAML
file. You can generate these for a whole ensemble with:

.. code-block:: console

  $  uv run python ./scripts/run_pysdm.py /path/to/your/build "your_ensemble" 3 --do_inputfiles


This will also make some directories so that you can run the model.


.. _do_run_model_pysdm:

Running, i.e. Time-stepping, the Model
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Run the PySDM 1-D KiD with the ``--do_run_model`` flag, either via ``run_sdm_1d_kid.sh``
or directly via ``run_pysdm.py``. This will output a number of ``.npy`` files (analogous
to Cleo's ``.zarr`` directory) in the output data directory, as well as a quickplot of the
cloud+rain water evolution for each run. By default, the files for each run will be written
in ``/path/to/your/build/pysdm/your_ensemble/bin/your_run_name`` (as per the settings in
your YAML config file for each run, generated by the ``inputfiles`` function in
``run_pysdm.py``).


.. _do_postprocess_pysdm:

Post-Processing the Output
~~~~~~~~~~~~~~~~~~~~~~~~~~~

Run the ``--do_postprocess`` stage to combine the ``.npy`` output of all the runs in
your ensemble into a single post-processed dataset (see
``src/sdm_1d_kid/pysdm/postprocess.py`` for details). By default, this post-processed
dataset is written in ``/path/to/your/build/pysdm/your_ensemble/postproc/``
(see ``run_pysdm.py``) as ``your_ensemble.zarr``.

The dataset has dimensions ``(ensemble, height, time)``, plus
``(ensemble, height, time_sds)`` for the superdroplet diagnostics and
``(ensemble, height, time_sds, radius_bin)`` or ``(ensemble, height, time_sds, radius_bin_dry)``
for the superdroplet (dry) size distributions. The radius bins are geometrically spaced, i.e.
equally spaced in logarithmic space. The superdroplet diagnostics are calculated every
``sddiags_every``-th output time, i.e. at the times of the ``time_sds`` coordinate. The parameters
for these diagnostics, including the radius bins (``r_bins_edges`` and ``r_bins_edges_dry``) can be
edited in the PySDM ``Settings`` class (``src/sdm_1d_kid/pysdm/helpers/settings.py``),
and in ``pysdm/postprocess.py``.

In PySDM the calculations often exclude the mass/volume of solute whereas Cleo includes it.
PySDM's radius excludes the solute volume, so ``radius_bin`` (also ``_lower``
and ``_upper``), and the distributions binned by it (``numconc_distrib``, ``mass_distrib``,
``reflectivity_distrib``), as well as ``reflectivity_dbz``, ``lwc``, ``lwp`` and ``numconc_d``,
exclude the solute mass/volume. In contrast, in Cleo all those variables account for solute.
Meanwhile, PySDM's ``mass_distrib`` (though not its bins) includes the solute mass (by assuming
the solute density ``rho_sol`` as done also by ``msol_mass_distrib``), and both PySDM's and
Cleo's ``dvol`` and ``dvol_sigma`` exclude the solute volume. The differences between PySDM and
Cleo from including/excluding solute are likely to be very small, except when comparing aerosol/haze.
In the description of certain variables you can see whether or not they account for solute
mass/volume and compare that with Cleo (see below).

Comparing PySDM and Cleo Datasets
###################################

It may be useful to compare what variables are common/different between Cleo and PySDM's
post-processed datasets. You can do this for example as follows:

.. code-block:: python

  import xarray as xr

  ds_pysdm = xr.open_zarr("/path/to/your/build/pysdm/your_ensemble/postproc/your_ensemble.zarr")
  ds_cleo = xr.open_zarr("/path/to/your/build/cleo/your_ensemble/postproc/your_ensemble.zarr")

  cleo_vars = set(ds_cleo.variables)
  pysdm_vars = set(ds_pysdm.variables)

  common = sorted(cleo_vars & pysdm_vars)
  cleo_only = sorted(cleo_vars - pysdm_vars)
  pysdm_only = sorted(pysdm_vars - cleo_vars)

  print("--- Common to Cleo and PySDM ---\n" + "\n".join(common)+ "\n-----")
  print("--- Only in Cleo ---\n" + "\n".join(cleo_only) + "\n-----")
  print("--- Only in PySDM ---\n" + "\n".join(pysdm_only) + "\n-----")

  print("--- Comparison Metadata of Common Variables ---")
  for name in common:
      a_name, b_name = "Cleo", "PySDM"
      a, b = ds_cleo[name], ds_pysdm[name]
      if a.attrs.get("units") != b.attrs.get("units") or a.dims != b.dims:
          print(f"{name} has units or dimensions difference:\n"
                f"units {a_name} vs. {b_name}: {a.attrs.get('units')!r} vs. {b.attrs.get('units')!r}"
                f"\ndims {a_name} vs. {b_name}: {a.dims} vs. {b.dims}"
                "\n-----")
      if a.attrs.get("long_name") != b.attrs.get("long_name"):
          print(f"{name} has long_name difference\n"
                f"{a_name}: {a.attrs.get('long_name')!r}\n{b_name}: {b.attrs.get('long_name')!r}"
                "\n-----")
      if a.attrs.get("description") != b.attrs.get("description"):
          print(f"{name} has description difference\n"
                f"{a_name}: {a.attrs.get('description')!r}\n{b_name}: {b.attrs.get('description')!r}"
                "\n-----")


You may also find it helpful to read our Sections on :ref:`normalising_distribs` and
